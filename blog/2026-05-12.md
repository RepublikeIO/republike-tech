# Tuesday, May 12th 2026

## Building the new feed

### The week in one sentence

The elastic paywall released. The next visible surface is the new feed — a single unified timeline, a clean header, and a synthesis surface citizens can use to actually understand what the community thinks instead of scrolling forever.

### Shipping  the new feed

The redesigned feed exists now in working code on both web and mobile. The shape:

**A single chronological timeline.**  We had four feed modes (Follow, Latest, Hot, News). Citizens picked one and stayed there, missing the others. The new feed is one column, sorted chronologically — every post that matters surfaces. Recency is the dominant signal, and a small per-viewer follow boost re-orders within each page so posts from people you care about rise a bit. Posts from a 30-minute-old stranger still beat a 90-minute-old follow — recency wins big gaps. The boost only matters at the margins, where pure chronology felt arbitrary anyway.

**A cleaner header.**  The left sidebar that competed with the feed for attention is gone. The items it carried — Bookmarks, Leaderboard, Governance, Founder Status, Invite Friends, FAQ, Create Post, Feedback — moved under the profile/settings menu opened from the avatar in the top bar. The feed is now the primary surface; secondary navigation is one tap away. Logo on the left, credits and notifications on the right, single column max-width.

**An activation signal.**  Above the feed sits a progress bar showing where the community is this week, counted weekly with a single cached query so the cost is effectively zero. Below the bar, a two-tab switcher: Your feed (the unified timeline) and Surprise me — locked behind the activation threshold for now, an explicit signal that the algorithm only earns the right to choose after the community contributes enough to justify it. Tapping Surprise me while locked nudges the user toward the progress bar with a pulse.

**Dive Deep, the synthesis surface.**  Each post now carries a Dive Deep trigger at the bottom-right where the bookmark used to live. The button surfaces a modal explaining the platform-level lock until the activation threshold is reached. The deeper goal is a synthesis view per topic — a structured summary of every angle the community has produced on a question — that gives Republike its real differentiator: a platform that helps citizens understand the conversation, not just produce more of it.

### Security  ongoing posture

A responsibly-disclosed vulnerability in the Inngest TypeScript SDK potentially exposed environment variables through the serve endpoint of any affected version. We were on an affected version. The fix shipped the same day — package bump on the elastic paywall branch — and the affected keys are queued for rotation. Discord receives a structured alert if the upstream signing path fails so future regressions surface fast.

The deeper pattern here matters more than the specific CVE: shared infrastructure means shared exposure. We're treating peer dependencies and bundled SDKs as part of the trust boundary now, not as third-party black boxes that just work. Same posture as the privacy work — assume every channel can fail, design so failure of any single one yields nothing useful in isolation.

### Onboarding hygiene

The signup flow now recovers from edge cases that previously stranded users. The most common one: clicking the verification link on a desktop browser while staring at the mobile app on your phone. The mobile app didn't know the verification happened and the user was stuck.

We fixed this by treating the verification screen as a live surface — it polls quietly while visible, refetches on app foreground, and exposes a manual "I've already verified" affordance for the explicit case. Three layers of detection, no path leaves the user trapped. Plus an auto-login on signup so the resend / polling flow has a session to work with, and a routing fix so a logged-in user with EMAIL_VERIFICATION status actually lands on the verification screen instead of being silently misrouted.

The forms beneath this got the same treatment. Registration and profile-completion forms now show a live checklist of validation rules and tick them off as the user types — progressive validation instead of "you'll find out what's wrong when you submit." Username availability is checked inline with a debounced server call. The shape is consistent enough that adding a new validated field is a matter of declaring the rule, not wiring up the UI.

### Onboarding carousel

The principle-acceptance carousel was previously implemented by pushing the same screen onto the navigation stack with different params — five stack entries that all looked alike, with the whole screen sliding sideways each time. Replaced with a real horizontal pager: only the text content moves, the illustration stays anchored. Responsive sizing so the layout adapts to short and tall phones without overlapping or leaving empty space. Small change with disproportionate quality-of-feel gain.

### ZK identity  defining the primitives

Continuing the architectural investigation. The work this week was largely below the waterline: a stacked-branch workflow that keeps the security-critical migrations independently mergeable from the redesign work, so the on-chain primitives we're building toward stay separable from product surface changes. The strategic memo from the previous cycle is the reference — phase 1 (off-chain `UserContract`) is feature-complete and providing the foundation we ship product against; phase 2 (non-custodial wallets, L2 evaluation) is where the next concentrated push goes once the new feed lands.
