# Monday, May 4th 2026

## Shipping the no-paywall release

### The week in one sentence

The version of Republike where you don't have to pay to enter is imminent. Staging validates clean, copy is final, and the polish pass that lands with it touches every surface a Free Citizen will see first.

### The release  elastic paywall, free entry

The contract-based access system has been on a feature branch for two weeks. This week we closed the gap between "built" and "shippable."

**Paywall screen, redesigned.**  The mobile plan picker is now a peer-list of options. Every plan, including Free, sits in the same card with the same row shape and a radio button. Free is no longer a fallback button at the bottom of the screen  it's a plan, listed next to Founding Citizen and Founding Father, with its own subtitle and its own primary CTA. The contrast between paid and free is signaled by what's checked or crossed in the benefits list below, not by where a button lives. A new subscriber and a Free Citizen pass through the same UI shape.

**Wording.**  Free is framed as a legitimate civic path, not a stripped-down option. "Start as a Free Citizen" replaces "Continue for free." The supporting copy describes what's possible (read, follow, join the conversation; upgrade anytime) instead of what's missing.

**Webapp parity.**  A Free Citizen signing up through the web now sees the same option, the same wording, the same path. The server-side mutation is shared between mobile and webapp  one source of truth for the PAY_WALL → ACTIVE transition. Whichever client a user enters from, the experience is identical.

**Empty states.**  A new Free Citizen first lands on mostly empty surfaces  bookmarks with nothing saved, a follow feed with no posts, hashtag pages they haven't joined. All of these had been using a single placeholder that said "No posts found / Retry." Wrong tone for someone who just arrived, and a misleading button to boot. We replaced it with screen-specific copy: bookmarks now has its own dignity ("Nothing saved yet  when you find a post worth keeping, tap the bookmark icon"); the follow feed invites you to follow citizens whose voice you care about; latest, hot, news, hashtag, and community feeds each say what their surface is for and what to do next. The Retry button is gone where it doesn't belong  pull-to-refresh handles transient cases.

A platform that asks people to participate has to communicate, even on its empty pages.

**Stuck users.**  Approximately 2,000 production users are parked at PAY_WALL  some on legacy tiers, some who refused to subscribe but couldn't proceed. The release migration handles them in one batch: every PAY_WALL user is moved to ACTIVE with a Free Citizen contract, restoring their access without requiring them to retry sign-up. Paying users keep their existing contracts. No one is deleted; no role is downgraded.

### Privacy hardening  ongoing

Continued the audit of every channel where user data could cross a trust boundary. This week's pass extended into the development environment  test paths previously had quiet exceptions that bypassed the production-equivalent flow, and we removed them so the verification path is exercised end-to-end in dev.

The principle: development should behave like production unless there's an explicit reason otherwise. Quiet exceptions are how issues survive into staging.

### Dev environment posture

Two related fixes around silent fallbacks.

**Refusing to silently hit production.**  When a missing env var was previously absorbed into a production URL fallback, a local session could write against live data without the developer noticing. Dev builds now refuse to start with the env unset, surface a clear message about how to fix it, and log the resolved backend at boot. The production fallback only applies in release builds, where it's correct by design.

**Removing the no-op email branch in dev.**  A condition in the email service had been short-circuiting every send in development for noise reduction. Useful at the time, terrible for exercising the verification path and the privacy posture end-to-end. Removed; the existing failure surface catches sender or template issues if they appear.

Neither was an incident. Both were the kind of dev-environment quietness that lets bugs survive deploy.

### ZK identity  defining the primitives

Continuing the architectural investigation into the migration toward a zero-knowledge identity protocol. This week's work was on the document trail: a full strategic memo describing the four-phase migration (off-chain primitives → non-custodial wallets and L2 selection → on-chain role registry → ZK attestations and verifiable credentials), each phase delivering value independently of the next.

A correction made explicit in the memo: the wallet model is non-custodial. The server derives wallets deterministically from a master seed and the user's identity, holds the keys on the user's behalf, and would hand them over if the user ever asked to take ownership. The user never sees a seed phrase, never installs an extension, never pays gas. Sovereignty doesn't have to look complicated to be real.

Phase 1  the off-chain `UserContract`  is stable and feature-complete. Its storage shape mirrors what an on-chain role registry would store: identifier, role, grant timestamp, expiry, source, status. When the chain layer comes in, the write path changes; the read path stays. That's why the elastic paywall release can ship now without waiting on any chain decision  the foundation is built so the chain can slot in later, not the other way around.
